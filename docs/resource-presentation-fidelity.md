# Resource presentation fidelity

`dist/resource-presentation.js` separates resource presentation from the harvesting simulation. It does not alter worker orders, pathing, queues, income, or mineral footprints.

## Mineral states and a corrected interpretation

The [pinned Liberty behavior catalog](https://raw.githubusercontent.com/Talv/sc2-data/1921f856b0443d4cbd366c472cd7984fa6a224d1/mods/liberty.sc2mod/base.sc2data/GameData/BehaviorData.xml) gives `DepletionThreshold=750` and `DepletionVariationCount=4`. The [Liberty actor catalog](https://raw.githubusercontent.com/Talv/sc2-data/1921f856b0443d4cbd366c472cd7984fa6a224d1/mods/liberty.sc2mod/base.sc2data/GameData/ActorData.xml) maps resource levels 0–3 to animation groups A–D, with smaller splats for levels 0–1. These justify discrete actor states rather than continuously shrinking the whole mineral mesh.

**750 is a depletion alert threshold, not an established visual-state boundary.** [Resource behavior field documentation](https://sc2mapster.wiki.gg/wiki/Data/Behaviors/Resource) explicitly describes it as the alert threshold and describes variations as divisions of remaining amount, while marking the capacity basis uncertain. The original audit's suggestion to use discrete states is sound, but it did not establish the boundary formula.

`mineralVisualState(node)` returns `-1` for empty/invalid fields and ordinal `0..3` otherwise. This implementation uses four equal divisions of `amount/capacity`, clamps at the fullest state, and places exact quarter boundaries in the larger state. Those divisions and boundary inclusivity are **inferred presentation policy**, awaiting native-client observation. They are not claimed as extracted engine code. Exported `MINERAL_DEPLETION_ALERT=750` remains separate from this calculation.

Keep immutable `capacity` on each mineral node: a full small 900 field and a large 1800 field depleted to 900 are different cases. [Void small-field data](https://raw.githubusercontent.com/Talv/sc2-data/1921f856b0443d4cbd366c472cd7984fa6a224d1/mods/void.sc2mod/base.sc2data/GameData/BehaviorData.xml) sets the small field's capacity to 900, while the [Void multiplayer override](https://raw.githubusercontent.com/Talv/sc2-data/1921f856b0443d4cbd366c472cd7984fa6a224d1/mods/voidmulti.sc2mod/base.sc2data/GameData/BehaviorData.xml) sets regular fields to 1800. Nodes without valid capacity explicitly fall back to the regular 1800 capacity. No hidden first-render snapshot guesses which field was initially small.

## Worker status

`workerStatus(building, entities, minerals)` returns `{count, ideal, label}` with text `Workers: count/ideal`, or `null` for unsupported, flying, planned, unfinished, or dead structures. The renderer can select a mineral or gas icon from the building type without changing the native-style text.

Completed grounded Command Centers count workers actively assigned to their associated mineral fields, including workers on the home leg and explicit Return Cargo orders with a mineral order saved in `resume`. Refineries count workers assigned to that specific Refinery, including hidden gas harvesters and gas-return orders. A gas worker's proximity to a Command Center never counts as mineral saturation. Dead, loaded, idle, and workers with only future queued harvesting are excluded. Explicit cargo return without a saved harvesting assignment is not treated as an assigned harvester.

The [Liberty actor catalog](https://raw.githubusercontent.com/Talv/sc2-data/1921f856b0443d4cbd366c472cd7984fa6a224d1/mods/liberty.sc2mod/base.sc2data/GameData/ActorData.xml) gives Command Centers a mineral label and search radius of eight game units, Refineries a separate vespene label, and hides worker status while flying. The module assigns each mineral to the nearest eligible grounded base of the displayed building's team, using stable ID tie-breaking. Its range check measures the nearest surfaces of both building and mineral footprints. Starting centers are generated at 230 world units, then snapping and overlap avoidance spread outer fields farther away; a base-center-only check incorrectly showed 8/12 rather than 12/16 at the actual opening. Polygon and circle surface checks include all eight starting fields without searching by the worker's current position. These association/search semantics are **an approximation**: exact native resource-search mechanics are not present in the catalog.

Ideal counts use two workers per associated live mineral field and three per nonempty Refinery. Multiplayer mineral ideal two is catalog-backed; [Blizzard's economy guide](https://news.blizzard.com/en-us/article/4488313/game-guide-economy) also distinguishes two workers per patch from three per geyser. Depleted and dying fields contribute no ideal capacity. A worker carrying the final cargo from an exhausted but not destroyed field remains counted until depositing; this presentation choice avoids losing that trip merely because its field became empty. Its exact native timing still requires comparison.

## Verification

`node tests/resource_presentation_fidelity.mjs` covers discrete states, alert separation, capacity metadata, two bases sharing a search area, workers returning near a different base, gas/refinery assignment, hidden harvesters, explicit cargo resumption, dead/loaded/idle/future-queued workers, final depleted-field trips, surface-aware starting fields, the complete actual snapped opening at 12/16 per base, and hiding ineligible structure labels. These are meaningful regressions for the stated policy, not proof of native actor thresholds, M3 clip equivalence, or native search behavior.
